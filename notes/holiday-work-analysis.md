# 法定假期出勤 · 分析

日期：2026-10-09 · 状态：**仅分析，未修改代码**

---

## 一、现状：假期出勤 = 白干

现在 App 对休息日的处理是**一刀切**：

```java
if (!WorkdayHelper.isWorkday(context, salarySettings, calendar)) {
    salarySnapshot.state = 0;      // STATE_REST_DAY
    return salarySnapshot;         // earned = 0
}
```

主卡显示：

```
● 国庆节、中秋节 · 今天不累计
¥ 0.00
```

**问题**：如果你真的在 10 月 1 日上了一整天班，App **不会记录任何东西** ——
累计收入少一天，工资日历里那天是空白。而这恰恰是**最赚钱的一天**（法定 3 倍工资）。

---

## 二、法律依据（这决定了倍率）

《劳动法》第 44 条：

| 情形 | 法定标准 | App 现状 |
|---|---|---|
| 工作日延长工作时间 | **150%** | ✅ 已支持（加班打卡） |
| 休息日工作，不能补休 | **200%** | ❌ 不支持 |
| **法定节假日工作** | **300%** | ❌ 不支持 |
| 调休上班日（如周六补班） | 正常 **100%** | ✅ 已支持（算工作日） |

> 2025 年起，法定节假日共 **13 天**：元旦 1、春节 4（含除夕）、清明 1、劳动节 2、端午 1、中秋 1、国庆 3。

---

## 三、关键难点：现有数据分不清"3 倍日"和"2 倍日"

看内置数据（2025 国庆）：

```
20250928:0:国庆节、中秋节    ← 调休上班
20251001:1:国庆节、中秋节    ← 法定 3 倍
20251002:1:国庆节、中秋节    ← 法定 3 倍
20251003:1:国庆节、中秋节    ← 法定 3 倍
20251004:1:国庆节、中秋节    ← 调休/周末 2 倍
...
20251008:1:国庆节、中秋节    ← 调休/周末 2 倍
```

**整个假期标的是同一个名字**，程序无法区分「法定 3 天」和「调休 4 天」。

**要精确，必须补一份「法定节假日」日期表**（每年 13 天）：

```
2025: 1/1, 1/28~1/31(春节含除夕), 4/4, 5/1~5/2, 5/31, 10/6(中秋), 10/1~10/3
2026: 1/1, 2/16~2/19(春节), 4/4, 5/1~5/2, 6/19, 9/25(中秋), 10/1~10/3
```

- 日期在表里 → 法定节假日 → **3 倍**
- 是休息日但不在表里 → 周末/调休 → **2 倍**

> 数据来源同现在：国务院办公厅每年 11 月前后发布的放假通知。

## 四、方案设计

### 4.1 交互：复用加班打卡的形态

休息日/节假日，主卡「今日已赚」上方出现同一位置的打卡行：

```
┌─────────────────────────────────────┐
│  10月1日 国庆节                      │
│  今天出勤了？              [ 打卡 ]   │   ← 点击
│  ¥ 0.00                             │
└─────────────────────────────────────┘

         ↓ 点击后

┌─────────────────────────────────────┐
│  10月1日 国庆节                      │
│  🎉 节假日出勤 · 3 倍  [ 取消 ]       │
│  ¥ 900.00                           │   ← 日薪 300 × 3
│  ● 法定节假日出勤 · 3 倍结算          │
└─────────────────────────────────────┘
```

两种形态：
- **法定节假日** → 「节假日出勤 · 3 倍」
- **周末/调休** → 「休息日出勤 · 2 倍」

### 4.2 计价

```
出勤收入 = 日薪 × 倍率
     法定节假日：× 3
     周末/调休：  × 2
```

**倍率基准需要你拍板**（公司政策不同）：

| 口径 | 10/1 上班（日薪 300） | 说明 |
|---|---|---|
| A. **总额 3 倍** | ¥900 | 多数公司做法，App 按这个算最简单 |
| B. 1 倍 + 3 倍 = 4 倍 | ¥1200 | 严格按"额外支付 300%"理解 |
| C. 按公司实际 | 可手动改倍率 | 设置里给一个数字输入 |

> 建议：**默认 A（3×/2×），但允许手动改** —— 因为各公司差别太大，写死一定会有人对不上。

### 4.3 出勤时长：先做"全天"，不做"按小时"

法定假期出勤**通常按整天算**（8 小时工作制），所以：
- 点一下 = 一整天
- 不做打卡计时（否则你 9 点打卡、17 点再点结束，中间忘点就乱了）

**但保留扩展位**：如果以后你想按实际时长算（比如只去了半天），
可以在打卡行上加「半天」选项 —— 结构支持，暂不实现。

### 4.4 必须归档（这是重点）

**绝对不能重蹈"加班费蒸发"的覆辙**：

```
出勤当天 → 写入 SalaryHistory（按 stamp 归档）
         → cumRollover 里把出勤天也计入累计
         → 累计天数 +1
```

否则第二天这笔钱同样会消失。

### 4.5 忘打卡怎么办

给一个**补录入口**：工资日历里**长按某一天** → 弹出「标记为出勤 / 取消出勤」。
（复用同一套存储，只是指定日期）

## 六、边界情况（要一起想清楚）

| 情况 | 建议处理 |
|---|---|
| **法定假期只上半天** | 先按全天算；后续可加「半天」按钮 |
| **出勤超过 8 小时** | 暂不叠加加班；先按 3 倍/2 倍封顶 |
| **春节 9 天假里只有 4 天是法定的** | 靠日期表区分：4 天 3×，其余 2× |
| **调休上班日（周六补班）** | 现在已按正常工作日处理（1×），**保持不动** |
| **忘记打卡** | 工资日历长按补录 |
| **打了卡但其实没上班** | 打卡行给「取消」按钮 |
| **跨月** | 归档按 stamp，天然支持 |

## 七、我的建议

**做，但分两步**：

**第一步（核心）**
- 法定节假日 3× / 周末 2× + 全天打卡
- 倍率可手动改（默认 3/2）
- 归档接入累计与工资日历
- 工资日历长按补录

**第二步（可选，看用不用得上）**
- 半天出勤
- 超出 8 小时部分按加班叠加

**不做**：自动判断你有没有上班 —— App 拿不到这个信息，只能靠你点一下。
（这也是为什么打卡按钮是必要的，而不是懒省事）

---

## 八、需要你决定的两件事

1. **倍率口径**：10/1 上班，你公司是给 **3 倍总额（¥900）** 还是 **1+3=4 倍（¥1200）**？
   （不确定就选"可手动改"，默认 3 倍）
2. **要不要"半天"选项**？还是先只做整天？
