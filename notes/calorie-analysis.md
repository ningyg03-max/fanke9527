# 「每样饮品多少卡热量」可行性分析

日期：2026-10-09 · 状态：**仅分析，未实现**

---

## 一、结论

| 目标 | 可行性 | 说明 |
|---|---|---|
| **技术上做出来** | ✅ 完全可行 | 不需要新权限、不依赖网络、改动量中等 |
| **得到「准确」数值** | ❌ 做不到 | 现有 8 个品类太粗，同类饮品热量可差 **50 倍** |
| **得到「粗略参考」** | ✅ 可以 | 误差 ±30%~±100%，只能当天数看，不能用来严格控卡 |

**核心矛盾**：App 记录的是「品类」（咖啡），而不是「具体产品」（星巴克中杯拿铁）。
热量取决于**具体配方**，品类这一层信息量不够。

---

## 二、为什么「准确」做不到：实测数据

按现有 8 个品类，各品类真实热量波动如下（数据来源：百度健康 / 知乎 / FatSecret，本次联网核查）：

| 品类 | 每 100ml 热量 | 波动 | 差异根源 |
|---|---:|---|---|
| 白开水 | 0 | — | — |
| 茶 | 0~1 | 小 | 无糖清茶≈0；一旦加糖就完全不同 |
| **咖啡** | **1.4 ~ 73** | **≈50×** | 美式 5 kcal/杯 vs 拿铁 150~220 kcal/杯 |
| **奶茶** | **30 ~ 100** | **≈3×** | 糖度、奶、珍珠、奶盖（一杯 500ml 全糖珍珠奶茶 ≈ 600 kcal） |
| **可乐/汽水** | **0 ~ 45** | **∞** | 零度可乐 0 vs 含糖可乐 43 |
| 果汁 | ~45 | 小 | 100% 果汁相对稳定 |
| **牛奶** | **34 ~ 70** | **≈2×** | 脱脂 34 / 低脂 45~50 / 全脂 60~70 |
| 其他 | ？ | — | 完全无法估算 |

### 关键证据

> **咖啡**：「一杯约 300ml 的拿铁（含全脂牛奶）热量约 150-220 大卡，而同样容量的美式仅 5-15 大卡」
> 折算每 100ml：美式 ≈ 1.4 kcal，拿铁 ≈ 50~73 kcal —— **相差约 50 倍**

> **可乐**：含糖可乐 43 kcal/100ml，零度可乐 **0 kcal/100ml**

> **奶茶**：无糖 30~50，全糖 60~80，全糖珍珠可到 100 kcal/100ml

**含义**：如果按「咖啡 = 某个固定值」估算，对喝美式的人会**高估 30 倍**，对喝拿铁的人会**低估 30 倍**。
这种精度下，热量数字的意义有限 —— 除非让用户能表达得更细。

## 三、三种技术方案

### 方案 A：内置估值表（最简单）

每种饮品内置一个 `kcal/100ml` 常量，按记录自动累计。

- ✅ 零成本、离线、无需用户输入
- ❌ 精度最差（上表所有问题都吃满）
- 适合：只想看个"大概量级"

### 方案 B：用户可编辑 + 细分品类（推荐）

1. 内置表给**保守默认值**
2. **设置页里每样饮品的热量可手动改**（用户自己知道喝的是什么）
3. 把高波动品类拆细：
   - 咖啡 → 黑咖啡 / 拿铁 / 其他咖啡
   - 可乐 → 含糖可乐 / 无糖可乐
4. 自定义饮品在「添加饮品」时可选填热量
5. 显示时一律标「约」

- ✅ 精度可控（取决于用户填写意愿）
- ✅ 离线、无需新权限
- ❌ 增加一点设置负担
- 适合：认真想看一下摄入量

### 方案 C：扫码/联网查询具体产品（最准，但工程量大）

扫描条码 → 查询食品数据库（或内置品牌热量库）。

- ❌ **App 目前没有任何网络权限**（`AndroidManifest` 里连 `INTERNET` 都没有）——
  要做就得新增联网权限，等于改变 App 的隐私画像（现在是纯离线工具）
- ❌ 需要接入第三方数据库（国内饮料数据源大多要商业授权）
- ❌ 用户每次喝水都要扫码 —— 与"一秒记录"的现有体验冲突
- 适合：专门做饮食记录的 App，不适合这个工具

## 四、若要实现：改动清单（方案 B）

### 数据层
| 改动 | 说明 |
|---|---|
| `DrinkTypes` 加 `kcalPer100ml(context, id)` | 内置返回默认表，自定义读存储 |
| 内置默认热量表 | 白开水 0 / 茶 0 / 咖啡 2 / 奶茶 55 / 可乐 43 / 果汁 45 / 牛奶 60 / 其他 0 |
| 自定义饮品格式扩展 | `custom_drinks` 从 `id,name,unit` 扩到 `id,name,unit,kcal`（**向后兼容：3 列旧格式视为未设置**） |
| 新增键 `drink_kcal_<id>` | 内置饮品的用户自定义热量（与 `drink_ml_<id>` 同构） |

### 计算（无存储格式变化）
```
单条记录热量 = 记录毫升 / 100 × 该饮品 kcal/100ml
今日热量 = Σ 今日所有记录
```
> 记录本身不用存热量 —— 按需计算即可。好处：改热量设置后历史数据自动跟着更新。

### UI
| 位置 | 改动 |
|---|---|
| 主界面喝水卡 | 加一行小字「今日约 XXX kcal」 |
| 统计页 | 汇总区加热量（今日 / 近7天 / 近30天） |
| 记录页 | 每条记录右侧加「≈ XX kcal」 |
| 选饮品面板 | 名称旁小字显示 `xx kcal/100ml` |
| 设置页 | 容量网格每行加一个热量输入框 |

### 工作量估算
- 数据层：小改（约 40 行）
- 计算：小（约 20 行）
- UI：**主要工作量**（5 个界面要加，约 200 行）
- 测试：可覆盖（验证热量累计、兼容旧格式）
- 总体：中等，一次性可完成

---

## 五、建议

1. **如果只是"想有个数"** → 做方案 A，主卡加一行小字，成本最低
2. **如果想认真看摄入量** → 做方案 B，并且**务必把咖啡拆开**（黑咖啡/拿铁），
   因为 50 倍差异的品类基本等于没估
3. **不要做方案 C** —— 会破坏 App 现在的"纯离线 + 一秒记录"特性
4. 无论哪个方案，界面上都应标明「**约**」/「估算值」，避免用户当成精确数据

### 一个更轻的替代思路

不做热量，改成**「糖分提醒」**：只标记饮品是否含糖（无糖/有糖两档），
统计「今日含糖饮品 N 杯」。信息量比假精确的热量数字更实用，改动也更小。
