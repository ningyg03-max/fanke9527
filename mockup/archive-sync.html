② 修复机制 · 差量同步
记录变更时算「归档口径贡献」的差额：
Δ = contribution(改后) − contribution(改前)
  → SalaryHistory.adjust(Δ) // 工资日历
  → cum_total += Δ // 累计总额
操作改前 → 改后Δ
补记出勤 3 倍0 → 900+900
取消出勤600 → 0−600
补记病假 60%300 → 180−120
取消请假0 → 300+300
🔑 为什么用"改前/改后"而不直接写死增减？
「取消请假」要把那天的钱恢复成整日工资（不是清零）—— 只有对比两个状态的贡献值才能做到正确回冲。
③ 保护规则 · 不会重复计算
✅ 已归档日（stamp ≤ cum_last_day）→ 立即同步金额
🚫 未归档日（含今天）→ 不碰金额，交给归档器自然带上
判定条件与外快完全相同：cum_last_day > 0 && stamp ≤ cum_last_day
→ 两套机制不会互相干扰，也不会重复进账。
