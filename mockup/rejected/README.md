# 评估过但没做的方案

这里放的是**分析过、但决定不做**的原型。留着是为了：
① 以后有人再提类似想法时，能直接看到当时的结论和原因
② 避免重复分析

---

## 1. 小人拿游戏机（2026-10-20）

**想法**：下班后 / 周末，小人拿着游戏机玩。

**结论：不做。**

**原因**：
- 「下班后一直低头打游戏」会把**下班喜悦**变成**沉迷手机**，观感是负的
- 每天看到同一个人低头玩，很快腻
- 加道具本身没问题，但收益不足以抵消复杂度

**当时的建议**：如果要做，只做「点一下掏出玩 5 秒」的彩蛋式互动，不改常态。

---

## 2. 侧视小人 + 墙上电视 + 马里奥（2026-10-20）

**想法**：小人侧过来拿手柄，墙上电视显示马里奥。

**结论：不做。**

**关键发现**（这是最有价值的部分）：

1. **马里奥反而没问题** —— 按电视屏幕自适应缩放后约 16×20 单位，
   在 292px 画布上**能清楚认出**红帽 / 脸 / 蓝背带。
   原以为「23×29px 会糊成色块」，实测**估得过于悲观**。

2. **真正的问题是小人没有侧面特征** ——
   它是个**绿色椭圆蛋**，从哪个角度看都是椭圆。
   光挪眼睛位置读不出「侧过来」，3/4 侧视看着像「正脸歪了」，
   纯侧视看着像「正面少了一只眼」。

   → 要做真侧视，必须给角色加**侧面轮廓**（后脑勺、鼻嘴侧影）或改身体几何 ——
   那不是「加一个姿势」，是**重画整个角色**。

3. **一致性成本被低估** —— 16 个姿势全是正脸，只有这一个侧脸，
   切换时会像「换了个人」。

**教训**：判断「能不能做」时，先问**这个角色的几何形状支持这个视角吗**。
扁平抽象的椭圆角色，天生不适合侧视。
