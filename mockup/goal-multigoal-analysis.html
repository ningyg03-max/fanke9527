存钱罐升级：多目标 + 完成确认

你提的三件事：① 所有页面显示开始日期 ② 完成后人工确认按钮 + 显示完成日期 ③ 完成后能加第二个目标

1现状盘点

落点现在显示什么有开始日期？
主界面主卡名称 · 百分比 · 里程碑条 · 已攒/还差/预计完成无
月度战报名称 · 进度条 · 累计已攒/还差无
设置对话框名称 · 金额 · 进度起算日期选择器有
小人语录「存钱罐过半了，有点小骄傲」不需要

关键发现：goal_start_stamp（起算日）已经存在，只是只在设置对话框里露过面。 所以「显示开始日期」是纯展示改动，风险很低。

!三个必须解决的难点

难点 ①：存储只能装一个目标

现在是 4 个扁平 key：goal_name / goal_amount_bits / goal_start_stamp / goal_celebrated。 新目标会直接覆盖旧目标，历史全丢。 要做多目标，必须换成列表 + 写迁移（把你现在这个目标转成列表第一条）。

难点 ②：两个目标的进度会重叠（真问题）

进度算法是「累加 stamp ≥ 起算日 的所有收入」。如果目标 1 起算 9/1、 目标 2 起算 10/15，那么 10/15 当天的收入会被两个目标各算一遍。

解法：目标 2 的起算日自动设为「目标 1 完成日的次日」， 并且已完成的目标把金额冻结（存下来，不再重算）—— 历史不会因为以后补录而变。

难点 ③：「完成」有两种时间，含义不同

时间含义谁记的
达标日进度第一次 ≥100% 那天程序自动
确认日你点「确认完成」那天你手动

两者可能差几天（攒够了但还没下单/还没到手）。 建议都记：卡片显示「达标日」，确认后显示「完成（确认）日」。

4存储怎么改（附迁移）

新格式（沿用工程惯例的分隔符字符串，和 salary_history 一致）：

goal_list = 名称|目标分|开始日|达标日|确认日|完成金额分
　　↓ 多条用 ; 分隔
MacBook Pro|2356000|20260901|20261014|20261015|2390000

· 确认日 = 0 → 这条是当前目标；非 0 → 已完成（进历史）
· 名称要清洗掉 | 和 ;（项目里已有同类做法）

一次性迁移（启动时检测，只跑一次）：

若 goal_list 不存在 且 goal_name 存在：
　goal_list = goal_name|goal_amount_bits|goal_start_stamp|0|0|0
　（旧的 4 个 key 保留不删，作为回退保险）

⚠️ 迁移是这次唯一有风险的地方。 你现在这个目标（MacBook Pro 23,560）已经在用了，转换必须无损。 我会：① 迁移只跑一次、幂等 ② 保留旧 key 不删 ③ 专门写迁移的回归测试（含「旧数据 → 新格式 → 数字完全一致」）。

需要你拍板 4 件事

  • 完成日期显示哪个？达标日（攒够那天）/ 确认日（你点确认那天）/ 两个都显示
  • 完成的目标在哪看？主卡堆叠显示 / 战报页加一块「已完成」 / 设置里
  • 确认时能改日期吗？默认今天，还是弹个日期选择器让你选（比如「昨天下的单」）
  • 开始日期能改吗？现在设置里有选择器；多目标后建议只在新建时可选，进行中不让改（避免进度跳变）
