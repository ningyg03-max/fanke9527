备份升级：指定路径 + 自动周期

先看 Android 的限制，再看能做成什么样。

1现在是什么样

项现状
导出方式CREATE_DOCUMENT → 系统文件选择器 → 你选个位置 → 写完就完
路径记忆没有。每次都要重新选
自动备份完全没有
历史版本没有。同名文件直接覆盖

所以你现在每次备份，都要手动点一遍「设置 → 工具与安全 → 数据备份 → 导出 → 选位置 → 确认」。 想起来才做，而「想起来」往往是最需要的时候已经晚了。

!先说过不去的坎：不能随便写路径

Android 10+ 的分区存储下，App 不能直接往任意路径写文件。 所以「让用户输一个路径字符串比如 /storage/xxx/backup」做不到：

方式可行说明
直接写任意路径✗分区存储禁止
MANAGE_EXTERNAL_STORAGE✗「所有文件访问权限」，上架会被拒；要用户去系统设置里手动开，体验很差
SAF 目录授权✓让用户选一次目录，之后这个目录就长期可用（可持久化授权）

结论：不是「输入路径」，而是「选一次目录」。 用户选完，App 记住那个目录，之后自动往里面写 —— 这是 Android 上唯一干净的做法， 而且体验其实更好（不用记路径字符串）。

2能做成什么样

核心机制：第一次「选择备份文件夹」时调 ACTION_OPEN_DOCUMENT_TREE， 拿到目录 URI 后调 takePersistableUriPermission 把它永久记住。 之后自动备份就往这个目录写，不再弹任何框。

自动备份
备份文件夹Download/SalaryJump
备份周期每天 22:00
保留份数最近 7 份
上次备份今天 22:00 · 成功
立即备份一次›

文件名带日期：SalaryJump-20261015.json —— 天然形成历史版本， 不会互相覆盖。按「保留份数」自动删掉最旧的。

3「周期」怎么实现（这里最需要你知道）

方案可行说明
AlarmManager✓ 工程里已有现成套路（PaydayReminder / WaterReminderScheduler 都在用）， 且已有 SCHEDULE_EXACT_ALARM 权限 + 开机重启接收器。复用即可
WorkManager✓ 更省电，但要新增依赖（本工程无 Gradle，加库麻烦）
⚠️ 必须诚实说的限制：国产 ROM（含三星）会杀后台、限制自启。 定时任务在「App 很久没打开」「被清理掉」的情况下可能不触发， 这不是我能绕过的 —— 系统层面的限制。

缓解办法：把「自动备份」做成尽力而为 + 打开 App 时补跑： 每次你打开 App 检查一次「距上次备份超过周期了吗」，超了就立刻补一次。 这样即使定时被系统杀了，只要你用 App 就不会漏太久。

比存钱罐多目标（v3.74）略小——大部分是复用现有的闹钟与备份代码。 纯 Java 可控的部分（文件名、周期判断、保留策略）我会抽成纯函数并写测试； 系统交互（选目录、闹钟）没法在沙箱里跑，只能靠真机验证。

还有两个要提前说清楚的点：
① 授权失效：用户可能自己删掉那个文件夹，或在系统里撤销授权。 这时自动备份要能失败而不崩，并在设置里提示「需重新选择文件夹」。
② 数据安全：备份文件是明文 JSON（现在的格式就是）。 放到 Download 这类公共目录，别的 App 理论上能读到 —— 里面有你的工资数据。 要不要加密？加密会增加复杂度（要设置密码/口令）。

需要你拍板 4 件事

  • 周期选项：每天 / 每周 / 每月，还是给「每 N 天」自由填？我建议 每天·每周·每月 三选一 + 指定时间
  • 保留份数：固定 7 份 / 30 份，还是可选？
  • 要不要加密？不加密最简单（明文 JSON）；加密要你设密码，且忘记就恢复不了
  • 失败怎么办：静默重试 / 发个通知告诉你 / 只在设置里记一行
